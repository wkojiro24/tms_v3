# 車両名寄せ機能 要件定義書

## 1. 目的

車両ナンバーの表記ゆれを統一し、データの信頼性を確保する。
**これが全ての分析・交渉材料の基盤となる。**

---

## 2. 現状の問題

### 2-1. 表記ゆれの実態

同じ車両に対して複数の表記が存在：
- `100`
- `100番`
- `品川100`
- `100 ` (末尾スペース)
- `１００` (全角数字)
- `100号`

### 2-2. 影響

| 問題 | 影響 |
|------|------|
| 按分計算が不正確 | 同じ車両が別車両として集計される |
| 推移分析ができない | 月次データが紐づかない |
| 重複計上のリスク | 同じデータが2回カウントされる可能性 |
| 顧客資料の信頼性低下 | 「データがおかしい」と指摘される |

---

## 3. 既存リソース

### 3-1. 既存テーブル: `vehicle_aliases`

既にスキーマに存在する：

| カラム | 型 | 説明 |
|--------|-----|------|
| tenant_id | BIGINT | テナントID |
| pattern | VARCHAR | 別名パターン（例: "100番"） |
| pattern_type | VARCHAR | 'exact' または 'regex' |
| vehicle_id | VARCHAR | 正規ナンバー（例: "100"） |
| active | BOOLEAN | 有効/無効 |

**このテーブルを活用する。**

### 3-2. 既存の車両テーブル: `vehicles`

正規ナンバーは `registration_number` カラムに格納されている。

## 4. 機能要件

### 4-1. 名寄せエンジン（コアロジック）

#### 機能概要
生の車両ナンバー文字列を受け取り、正規化されたナンバーを返す。

#### 入力
- 生の車両ナンバー文字列（例: "100番", "品川100"）

#### 出力
- 正規化された車両ナンバー（例: "100"）
- または見つからない場合はnull

#### 処理フロー

```
入力: "100番"
  ↓
[ステップ1] 基本正規化
  - 前後の空白削除
  - 全角→半角変換（数字のみ、英字サフィックスは保持）
  - 内部空白削除
  ↓ "100番"
  
[ステップ2] 正規ナンバーとして検索
  - vehiclesテーブルで registration_number = "100番" を検索
  ↓ 見つからない
  
[ステップ3] エイリアステーブルで検索
  - vehicle_aliases で pattern = "100番" を検索
  ↓ 見つかった → vehicle_id: "100"
  
[ステップ4] パターンマッチング
  - "100番" → "番"を削除 → "100"
  ↓ "100"
  
[ステップ5] 再度検索
  - vehicles テーブルで registration_number = "100" を検索
  ↓ 見つかった
  
出力: "100"
```

#### よくあるパターン

| パターン | 例 | 変換後 | 備考 |
|----------|-----|--------|------|
| 「番」付き | "100番" | "100" | 「番」は削除 |
| 地名付き | "品川100" | "100" | 地名部分は削除 |
| 「号」付き | "100号" | "100" | 「号」は削除 |
| 全角数字 | "１００" | "100" | 全角→半角変換 |
| 空白混入 | "100 " | "100" | 空白削除 |

#### ⚠️ 重要な例外ルール：英字サフィックスの保持

**末尾の英字サフィックス（A, B, C等）は必ず保持する**

| 入力 | 変換後 | 理由 |
|------|--------|------|
| 100A | 100A | Aは意図的な識別子 |
| 100B | 100B | Bは意図的な識別子 |
| 100番A | 100A | 「番」は削除、「A」は保持 |
| 品川100A | 100A | 地名削除、「A」は保持 |
| １００Ａ | 100A | 全角→半角、Aは保持 |
| 100 A | 100A | 空白削除、Aは保持 |

**理由:**
- `100` と `100A` は**別の車両**として運用されている
- A, B, C などは車両を区別するための意図的な識別子
- これを削除すると別車両が誤って統合されてしまう

**判定ロジック:**
- 数字の後に続く1〜2文字の英字（A-Z, a-z）はサフィックスとして保持
- 例: `100A`, `100AB`, `200C` など

#### パターンマッチングの優先順位

1. **完全一致**: vehicle_aliases の exact パターン
2. **正規表現**: vehicle_aliases の regex パターン  
3. **自動パターン（サフィックス保持あり）**:
   - `{地名}{数字}{英字サフィックス?}{番|号}` → `{数字}{英字サフィックス?}`
   - 例: "品川100A番" → "100A"
4. **自動パターン（サフィックス保持なし）**:
   - `{地名}{数字}{番|号}` → `{数字}`
   - 例: "品川100番" → "100"

#### 未マッピング番号の記録

名寄せできなかった番号は記録し、管理画面で確認できるようにする。

**記録する情報:**
- 生の番号
- クリーニング後の番号
- 出現回数
- 最初に出現した日時
- 最後に出現した日時

**新規テーブル: `unmapped_vehicle_numbers`**

| カラム | 型 | 説明 |
|--------|-----|------|
| tenant_id | BIGINT | テナントID |
| raw_number | VARCHAR | 生の番号 |
| cleaned_number | VARCHAR | クリーニング後の番号 |
| occurrence_count | INT | 出現回数 |
| first_seen_at | TIMESTAMP | 最初の出現日時 |
| last_seen_at | TIMESTAMP | 最後の出現日時 |
| resolved | BOOLEAN | 解決済みフラグ |
| resolved_to | VARCHAR | 解決後の正規ナンバー |
| notes | TEXT | メモ |

### 4-2. インポート時の自動名寄せ

#### 機能概要
Excel/CSVインポート時に、自動的に名寄せを実行する。

#### 要件

1. **インポート処理中に名寄せを実行**
   - 車両ナンバーを読み取ったら、即座に名寄せエンジンに渡す
   - 正規化されたナンバーでDBに保存

2. **名寄せ結果の記録**
   - 元の表記 → 正規化後の表記 を記録
   - インポートログに含める

3. **警告の表示**
   - 名寄せできなかった番号があれば警告
   - インポート後のサマリーに表示

#### 処理例

```
インポートファイル:
  行1: 車番: "100番", 売上: 8000000
  行2: 車番: "100A番", 売上: 5000000
  行3: 車番: "品川200", 売上: 9000000

処理:
  行1: "100番" → 名寄せエンジン → "100"
  行2: "100A番" → 名寄せエンジン → "100A" (Aを保持！)
  行3: "品川200" → 名寄せエンジン → "200"
  
保存:
  { vehicle_code: "100", value_numeric: 8000000 }
  { vehicle_code: "100A", value_numeric: 5000000 }
  { vehicle_code: "200", value_numeric: 9000000 }
  
ログ:
  ✓ "100番" → "100" に名寄せしました
  ✓ "100A番" → "100A" に名寄せしました (サフィックス保持)
  ✓ "品川200" → "200" に名寄せしました
```

#### 機能概要
ファイルをアップロードした時点で、名寄せ結果をプレビュー表示する。

| 5 | 品川200 | 200 | ✅ 正常 | 名寄せされました |
| 8 | 999 | 999 | ⚠️ 警告 | 車両が見つかりません |
| 12 | XYZ | XYZ | ⚠️ 警告 | 車両が見つかりません |

#### サマリー表示

```
インポートプレビュー結果

総行数: 50行
✓ 正常: 45行
```

### 4-4. 重複データ検出

#### 機能概要

以下3種類の重複を検出する：

#### 4-4-1. 既存データ内の重複

同一車両・同一月・同一メトリクスが複数存在するケースを検出。

**検出条件:**
```
vehicle_code = "100"
AND month = "2024-01"
AND metric_key = "revenue"
AND COUNT(*) > 1
```

**表示例:**
```
⚠️ 重複データが見つかりました

車両: 100
対象月: 2024年1月
メトリクス: revenue (売上)
重複件数: 2件

詳細:
  ID: 12345, 値: 8000000円, 登録日: 2024-11-01
  ID: 12789, 値: 8000000円, 登録日: 2024-11-15

アクション:
- [データを確認]
- [古いデータを削除]
- [新しいデータを削除]
```

#### 4-4-2. インポートデータと既存データの重複

今からインポートしようとしているデータが既に存在するケースを検出。

**検出タイミング:** インポート前のプレビュー時

**表示例:**
```
⚠️ 以下のデータは既に存在します

車両: 100, 対象月: 2024年1月, メトリクス: revenue
既存値: 8000000円
新規値: 8200000円

アクション:
- [上書き] - 既存データを上書き（8200000円に更新）
- [スキップ] - このデータをスキップ（既存の8000000円を維持）
- [キャンセル] - インポート中止
```

#### 4-4-3. 名寄せ後の重複

異なる表記だが、名寄せ後に同一になるケースを検出。

**例:**
```
行2: "100番" → 名寄せ後 "100"
行8: "品川100" → 名寄せ後 "100"
同一月、同一メトリクス
→ 同じファイル内で重複！
```

**表示例:**
```
⚠️ 名寄せ後に重複が発生します

行2: "100番" → "100" (売上: 8000000円)
行8: "品川100" → "100" (売上: 8200000円)

どちらのデータを使用しますか？
- [行2を使用] (8000000円)
- [行8を使用] (8200000円)
- [平均値を使用] (8100000円)
- [両方をスキップ]
```

**重要な例外:**
```
❌ これは重複ではない:
行2: "100番" → "100"
行5: "100A番" → "100A"

理由: 100 と 100A は別の車両
```

- 正規ナンバーで絞り込み

## 5. 非機能要件

### 5-1. パフォーマンス

- インポート時の名寄せ処理: 1レコードあたり平均10ms以内
- プレビュー表示: 1000行のファイルで3秒以内
- 重複チェック: 10,000レコードのチェックで5秒以内

### 5-2. データ整合性

- 名寄せ処理は必ずログに記録
- 元のデータ（生の番号）も保持（metadata JSONに記録）
- 名寄せ前後のデータを比較できること

### 5-3. ユーザビリティ

- 未マッピング番号は管理画面で一目で分かること
- エイリアス登録は3クリック以内で完了
- エラーメッセージは具体的で分かりやすいこと

## 6. テストケース

### 6-1. 名寄せエンジンのテスト

| 入力 | 期待される出力 | 理由 |
|------|----------------|------|
| "100" | "100" | 既に正規形式 |
| "100番" | "100" | 「番」を削除 |
| "品川100" | "100" | 地名を削除 |
| "１００" | "100" | 全角→半角 |
| "100 " | "100" | 空白削除 |
| "100A" | "100A" | サフィックス保持 |
| "100A番" | "100A" | 「番」削除、A保持 |
| "品川100A" | "100A" | 地名削除、A保持 |
| "１００Ａ" | "100A" | 全角→半角、A保持 |
| "100 A" | "100A" | 空白削除、A保持 |
| "100AB" | "100AB" | 2文字サフィックス保持 |
| "100号A" | "100A" | 「号」削除、A保持 |

### 6-2. 重複検出のテスト

**ケース1: 名寄せ後の重複（エラーになるべき）**
```
行1: "100番" → "100"
行5: "品川100" → "100"
同一月、同一メトリクス
→ ⚠️ 重複として検出される
```

**ケース2: サフィックス違いは重複ではない（正常）**
```
行1: "100番" → "100"
行5: "100A番" → "100A"
→ ✅ 重複ではない（別車両）
```

**ケース3: 異なるメトリクスは重複ではない（正常）**
```
行1: "100番", metric: "revenue" → "100"
行5: "100番", metric: "distance" → "100"
→ ✅ 重複ではない（メトリクスが異なる）
```

## 8. 注意事項・制約

### 8-1. 絶対に守るべきルール

1. **サフィックス（A, B, C等）は絶対に削除しない**
   - 100 と 100A は別の車両
   - これを間違えると致命的

2. **名寄せ前のデータも保持する**
   - 元の表記をmetadataに記録
   - 監査・検証のため

3. **エイリアステーブルが最優先**
   - 管理者が登録したエイリアスが自動パターンより優先
   - 例外ルールを柔軟に設定できるようにする

### 8-2. 想定される課題

1. **新しい表記ゆれの発生**
   - 定期的に未マッピング番号を確認
   - エイリアスを追加登録

2. **正規表現の保守**
   - 複雑な正規表現は避ける
   - 可能な限り完全一致で登録

3. **過去データへの適用**
   - 既存データを遡って名寄せし直す機能が必要か？
   - → 別途検討（Phase 1以降）
