# お知らせ機能 要件定義書

## 概要

### 目的
- 社内公式連絡のアーカイブ・検索機能
- リアルタイム通知はLINEWORKSを使用するため、本機能は記録保存と検索を主目的とする

### 設計方針
- シンプルかつ最小限の機能
- 閲覧専用（通知機能は持たない）
- 管理のしやすさ重視

---

## 機能要件

### 1. お知らせ投稿

#### 投稿権限
- **全ユーザー**が投稿可能（管理者に限定しない）

#### 基本項目
| 項目名 | 型 | 必須 | 説明 |
|--------|-----|------|------|
| タイトル | string | ◯ | お知らせのタイトル |
| 本文 | text | ◯ | 本文（Markdown対応を検討） |
| カテゴリ | string | - | 自由入力（履歴から選択可能） |
| 重要フラグ | boolean | - | 固定表示用 |
| 添付ファイル | attachment | - | 複数添付可 |
| 投稿日時 | datetime | 自動 | 投稿時に自動設定 |
| 投稿者 | user_id | 自動 | ログインユーザーを自動設定 |

### 2. カテゴリ機能

#### 仕様
- **自由入力形式**
- 過去に使用されたカテゴリを履歴として表示
- 入力時にオートコンプリートで候補を表示
- 新規カテゴリも随時作成可能

#### カテゴリ例
- 人事
- 総務
- 安全
- 経理
- 業務連絡
- その他

### 3. 一覧表示

#### 表示順
- 重要フラグ付きを上部に固定
- その後は投稿日時の新しい順

#### 表示項目
- タイトル
- カテゴリ
- 投稿者
- 投稿日時
- 重要マーク（重要フラグがある場合）

#### フィルタリング
- カテゴリ選択（履歴から）
- 日付範囲
- キーワード検索（タイトル・本文）

### 4. 詳細表示

- タイトル
- 本文（フルテキスト）
- カテゴリ
- 投稿者
- 投稿日時
- 添付ファイル（ダウンロード可能）

### 5. 編集・削除

- 投稿者本人および管理者のみ編集・削除可能
- 削除は論理削除（soft delete）

---

## 含めない機能

以下の機能は意図的に含めない：

- 既読管理・未読管理
- プッシュ通知
- 対象者の絞り込み（部署別・拠点別など）
- コメント機能
- リマインダー機能

## データモデル

### announcements テーブル

```ruby
create_table :announcements do |t|
  t.references :tenant, null: false, foreign_key: true
  t.references :user, null: false, foreign_key: true  # 投稿者

  t.string :title, null: false
  t.text :body, null: false
  t.string :category
  t.boolean :important, default: false
  t.datetime :discarded_at  # 論理削除用

  t.timestamps
end

add_index :announcements, [:tenant_id, :created_at]
add_index :announcements, [:tenant_id, :category]
add_index :announcements, :discarded_at
```

### 添付ファイル
- Active Storageを使用
- `has_many_attached :attachments`

## 実装優先度

1. **Phase 1（MVP）**
   - 投稿・一覧・詳細の基本CRUD
   - カテゴリ自由入力（履歴なし）
   - 重要フラグ

2. **Phase 2**
   - カテゴリ履歴・オートコンプリート
   - 添付ファイル対応
   - 検索・フィルタリング

3. **Phase 3（必要に応じて）**
   - Markdown対応
   - 一覧のページネーション最適化

---

## 備考

- LINEWORKSとの棲み分け：リアルタイム通知はLINEWORKS、アーカイブ・検索は本機能
- 既存の `announcements` テーブルが存在する場合は、要件に合わせてマイグレーション追加
